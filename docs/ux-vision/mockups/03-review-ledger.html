Annotations

  • 1Proposals group by provenance (the capture or watch that spawned them) because provenance-siblings share a fate — if Tuesday's note was real, its three extracted tasks probably all are.
  • 2Keyboard-first triage. Target: ten proposals in under a minute. If daily review takes longer than that, proposal volume — not the user — is what gets fixed.
  • 3A proposal is a diff, not a notification: before → after, author, confidence, reasoning, receipts. Low-confidence proposals say so and are never batch-accepted.
  • 4The quoted source excerpt with the trigger phrase highlighted — judge the proposal without leaving the card; one click to the full immutable entry.
  • 5Dismissal is a signal: “never propose this pattern” tunes the agent. Repeatedly-dismissed patterns must stop appearing.
  • 6Batch-accept only within one provenance group, only when every member is high-confidence.
  • 7Filterable by agent/verb/object/time — “what has the Researcher done all week?” is one query, not an archaeology dig.
  • 8Everything auto-applied stays undoable from the Ledger, indefinitely. Human actions are logged too — this is the shared surface's shared history, not an AI-only audit log.
  • 9Undo events are visible and consumed as training feedback — the loop that keeps annotate-tier trustworthy enough to stay automatic.
